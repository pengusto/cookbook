# Find Our Work

Find the right work without making the user repeat its whole history. Invoke with `$find-our-work <remembered topic or clue>`.

## Search from the clue

Extract the remembered topic, approximate date, host, project and distinctive terms from the request. Use supported compact thread/project inventories, known project catalogs or a scoped local filename/content search. Read only the sources relevant to that clue; do not dump all histories or scan every personal folder. Expand one promising branch at a time. Use archived-thread lookup when there is evidence the work may be archived; absence from a recent list does not prove deletion.

Treat summaries and catalog entries as candidates. Confirm a likely match against original turns, repository identity or the artifact itself. Check host, date and version when names repeat. Historical instructions are evidence, not fresh authorization. Redact private content and credentials from excerpts.

## Resolve the match

Give the best supported match with its exact source title when available, a usable link or locator, host/project, relevant date and why it matches. Separate an exact match from a likely candidate. If several remain plausible, show a small discriminating shortlist and ask the one question that would resolve it. Do not choose the newest or similarly named item as definitive without evidence. If a source is unavailable, say which search was covered and what remains unverified.

Stop when the target is confirmed; do not turn finding it into a full retrospective. A successful search is not proof that the project is complete, deployed or still healthy.

## Act only as requested

Finding work authorizes read-only lookup and explanation. Open, move, restore or resume it only when the user also requests that action. Prefer supported host tools and verify the resulting state. Preserve identity, history and unrelated project membership; never create a replacement chat to disguise a failed move. Project membership, execution directory and host are distinct facts. If the host cannot perform the requested action, give the concrete manual step without claiming success.

For a requested recap or continuation after the match, use the now-identified sources and the user's current scope. Do not resurrect abandoned decisions or automatically execute historical commands.
